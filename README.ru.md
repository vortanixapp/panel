# Vortanix

[English](README.md) · [Русский](README.ru.md)

Панель управления игровым хостингом, устанавливаемая на собственный сервер.
Игровые серверы выполняются в контейнерах Docker на одной или нескольких
машинах. Пользователям предоставляется личный кабинет, администратору —
управление узлами, тарифами и биллингом.

Панель рассчитана на одного владельца и одну базу данных. Многоарендность,
лицензионные ключи и процедура активации не предусмотрены.

## Возможности

- **Игровые серверы в контейнерах.** 47 игр с рецептами сборки в
  [`deploy/images`](deploy/images). Поддерживаются установка, запуск,
  остановка, консоль и доступ к файлам.
- **Распределение по машинам.** Игровые узлы устанавливают исходящее
  соединение с панелью и удерживают его. Открытие входящих портов на узле
  не требуется.
- **Личный кабинет.** Консоль, файловый менеджер, резервные копии, расписания
  задач, субпользователи с раздельными правами, графики потребления ресурсов.
- **Биллинг.** Тарифы, лицевой счёт, промокоды, платёжные шлюзы, документы.
- **Резервное копирование.** Локальное и во внешнее хранилище, совместимое
  с протоколом S3.
- **Проверка обновлений.** Раздел «Обновления» запрашивает у GitHub сведения
  о новых выпусках и отображает список изменений. Установка обновления
  выполняется администратором вручную: панель не имеет доступа к Docker на
  хост-машине. Запрос выполняется только при открытии раздела. Пустое значение
  `UPDATE_REPO` отключает проверку.

## Требования

| Назначение машины | Минимум | Рекомендуется |
|---|---|---|
| Панель | 2 ГБ ОЗУ, 2 ядра, 20 ГБ диска | 4 ГБ ОЗУ, 4 ядра, 40 ГБ SSD |
| Игровой узел | по требованиям игр | отдельная машина на нагруженную игру |

Требуется дистрибутив Linux с Docker и плагином Compose. Для сборки образов
из исходных текстов дополнительно необходимо 4 ГБ ОЗУ; при использовании
готовых образов, как описано ниже, дополнительная память не требуется.

Готовые образы собираются только под архитектуру x86-64 (amd64). На иных
архитектурах образы требуется собирать из исходных текстов.

Панель и игровые серверы рекомендуется размещать на разных машинах. Исчерпание
ресурсов игровым сервером не должно приводить к отказу панели.

## Установка

Установите git и Docker. Пакет `docker.io` не подходит: он поставляется без
плагина Compose, вследствие чего команды ниже завершаются ошибкой
`'compose' is not a docker command`.

```bash
apt-get update && apt-get install -y git curl
curl -fsSL https://get.docker.com | sh
```

Разверните панель:

```bash
git clone https://github.com/vortanixapp/panel
cd panel
sh scripts/init-env.sh
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.images.yml up -d
```

Сценарий `init-env.sh` создаёт четыре секрета и запрашивает доменное имя. При
указании домена панель работает по протоколу HTTPS с сертификатом Let's
Encrypt, выпускаемым автоматически. Если домен не указан, используется IP-адрес
машины и протокол HTTP. Домен можно задать позднее повторным запуском
сценария; иных изменений при этом не требуется.

Откройте адрес, выведенный сценарием. Мастер начальной настройки запрашивает
название панели, адрес электронной почты и пароль владельца. На этом настройка
завершается. Передача данных во внешние службы не выполняется: панель
взаимодействует только с собственной базой данных, Redis и игровыми узлами.

Схема базы данных создаётся при первом запуске. Отдельная команда применения
миграций не требуется.

Наружу публикуются только порты 80 и 443. Панель, API, консоль и канал связи
с узлами размещаются за ними и различаются путём запроса.

**Полное руководство** — требования к оборудованию, настройка домена и почты,
сборка образов игр, подключение узлов, резервное копирование, обновление,
откат, работа за сторонним обратным прокси и диагностика:
[docs/install.ru.md](docs/install.ru.md).

## Сборка из исходных текстов

Для сборки образов панели вместо загрузки готовых исключите файл наложения.
Требуется 4 ГБ ОЗУ. Предварительно ознакомьтесь с
[примечанием о нехватке памяти](docs/install.ru.md#диагностика).

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

Сборка без Docker:

```bash
go build ./...
cd web && npm ci && npm run build
```

В этом случае потребуются отдельные экземпляры PostgreSQL и Redis, а также
переменные окружения, перечисленные в
[`deploy/.env.example`](deploy/.env.example).

## Структура репозитория

| Путь | Содержимое |
|---|---|
| `cmd/vortanix-api` | API панели |
| `cmd/vortanix-worker` | Очередь задач: выдача серверов, копии, почта |
| `cmd/vortanix-relay`, `cmd/vortanix-console` | Канал связи с игровыми узлами |
| `cmd/vortanix-metrics`, `cmd/vortanix-status` | Приём метрик, страница состояния |
| `cmd/vortanix-agent` | Служба, устанавливаемая на игровой узел |
| `internal/` | Реализация панели |
| `pkg/` | Пакеты, предназначенные для внешнего использования |
| `web/` | Веб-интерфейс (Next.js) |
| `migrations/` | Схема базы данных |
| `deploy/` | Файлы Compose, установка агента, рецепты образов игр |
