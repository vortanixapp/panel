# Vortanix

Панель управления игровым хостингом, устанавливаемая пользователем на свой VPS.
Один Go-модуль (панель + агент) и одно приложение Next.js. Продукт
самостоятельный: с инфраструктурой Vortanix не связан ничем — ни лицензиями, ни
биллингом, ни обращениями наружу.

Открытый репозиторий. Закрытая часть (биллинг, выкатка) живёт отдельно,
в `F:\vortanixproject`, и сюда не переносится.

## Проверка правки

```bash
go build ./...                    # из корня, это один модуль
go vet ./...
go test ./...
gofmt -l .                        # должно печатать пусто
cd web && npx tsc --noEmit
```

`npm run lint` в `web/` — ловушка: eslint не установлен, `next lint` открывает
интерактивный визард и виснет. Проверка фронта — только `tsc --noEmit`.

## Карта

| Куда | Что |
|---|---|
| `cmd/vortanix-*` | точки входа: api, worker, relay, console, metrics, status |
| `cmd/vortanix-agent` | демон на игровой ноде |
| `internal/api` | панель: auth, серверы, ноды, платежи клиентов хостера |
| `internal/agent` | Docker, файлы, консоль на ноде |
| `internal/relay`, `internal/console` | связь с нодами: порты на нодах не открываются |
| `internal/worker` | очередь задач |
| `pkg/` | общий код: gamecatalog, protocol, secretbox |
| `web/` | панель, Next.js + shadcn/ui |
| `migrations/core` | схема; `deploy/images` — рецепты сборки 48 игр |

## Стиль

- **Комментариев в коде не писать.** Ни поясняющих, ни заголовочных, ни
  докстрок. Код объясняет себя именами и структурой; если строка непонятна без
  пояснения — переписать строку, а не приписывать к ней текст.
- Исключение — не комментарии, а директивы: `//go:build`, `//go:generate`,
  `//nolint`, `// Deprecated:`, `// @ts-ignore`, `/* eslint-disable */`.
  Их читают инструменты, снятие любой из них — поломка сборки или проверок.
- Причина правки живёт в сообщении коммита. Раз в коде пояснений нет, коммит
  остаётся единственным местом, где записано, что ломалось и почему выбран
  такой ответ, — писать его подробно.
- Коммиты по-русски, без префиксов вида `feat:`. Сообщение — результат для
  пользователя: «Обновления ставятся по кнопке; двойной запуск устранён».
- Не глушить ошибки заглушками `null` и `?? ""` — ошибка должна подниматься.

## Схема и миграции

- Установка одна, база одна. Столбец `tenant_id` остался от мультиарендной
  версии и держит постоянное значение: он в сотнях запросов, вынимать его
  ради косметики дороже, чем оставить.
- Новая миграция — следующий свободный номер, только вперёд. Номер `055`
  пропущен, не переиспользовать.
- Старые файлы миграций не редактируются: тот же каталог накатывается на уже
  существующие установки.

## Окружение (Windows)

- Рабочий каталог между вызовами Bash сбрасывается. Абсолютные пути в форме
  `F:/vortanix-oss/...`, не полагаться на `cd` из прошлой команды.
- `bash` из PATH ведёт в WSL-дистрибутив docker-desktop, а не в git-bash.
  Скрипты запускать через инструмент Bash, а не из PowerShell.
- Поиск по коду — инструмент Grep, а не `grep -r`: иначе поиск уходит
  в `web/node_modules`.

## Без спроса не делать

- `git push`, `git reset --hard`, удаление веток.
- Публикация репозитория: до неё остаются картинки лендинга без прав,
  вендорские адреса в дефолтах и неработающая установка.
