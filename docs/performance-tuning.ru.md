## Процессор

Игровые серверы чувствительны к падению частоты. Включите режим `performance`
(в Debian пакет называется `linux-cpupower`):

```bash
sudo apt-get install -y linux-tools-common linux-tools-generic
sudo cpupower frequency-set -g performance
cpupower frequency-info | grep "current policy"
```

Чтобы режим пережил перезагрузку, используйте `tuned` с профилем
`latency-performance` или юнит systemd, который выполняет команду при загрузке. На
виртуальных машинах управление частотой часто недоступно: решает хост, и менять
нечего.

Оставьте `irqbalance` включённым. Привязку контейнеров к ядрам (`cpuset`) панель
не делает намеренно: без знания топологии и нагрузки она чаще вредит.

## Память и swap

Контейнер никогда не уходит в swap: агент запускает его с `--memory-swap`, равным
лимиту памяти. Swap важен только для самого хоста.

```ini
vm.swappiness = 10
```

Небольшой swap (1–2 ГБ) лучше его отсутствия: ядро вытеснит редко используемые
страницы системных служб, а не убьёт игровой сервер.

Java-играм (Minecraft и другим) помогают прозрачные большие страницы в режиме
`madvise` вместе с флагом JVM `-XX:+UseTransparentHugePages` в параметрах запуска
сервера:

```bash
cat /sys/kernel/mm/transparent_hugepage/enabled
echo madvise | sudo tee /sys/kernel/mm/transparent_hugepage/enabled
```

Режим `always` не ставьте: он замедляет другие программы и даёт скачки задержек.

## Сеть (UDP)

Большинство игр шлёт UDP. При наплыве игроков стандартные буферы переполняются, и
пакеты теряются молча. Файл `/etc/sysctl.d/99-vortanix.conf`:

```ini
net.core.rmem_max = 26214400
net.core.wmem_max = 26214400
net.core.rmem_default = 1048576
net.core.wmem_default = 1048576
net.core.netdev_max_backlog = 16384
net.core.somaxconn = 4096
net.netfilter.nf_conntrack_max = 262144
net.netfilter.nf_conntrack_udp_timeout = 30
net.netfilter.nf_conntrack_udp_timeout_stream = 60
```

```bash
sudo sysctl --system
```

Ключи `nf_conntrack` есть только при загруженном модуле (Docker его загружает).
Если в `dmesg` видно `nf_conntrack: table full`, увеличьте `nf_conntrack_max`.

Потерянные пакеты видны здесь, растущие числа означают, что буферы малы:

```bash
netstat -su | grep -i "receive errors\|buffer errors"
```

## Диск и файловая система

- **NVMe или SSD** под `/var/lib/vortanix` и `/var/lib/docker`. Миры, логи и файлы
  игр это случайные чтения и записи, обычный диск проявится лагами.
- **XFS** лучший выбор: агент ограничивает диск сервера проектными квотами
  (`setquota`, `repquota`), которые XFS поддерживает с опцией монтирования
  `prjquota`, а кэш установки копирует файлы через `reflink`, и XFS его тоже
  поддерживает. Создавайте с включённым reflink (по умолчанию с xfsprogs 5.1):

```bash
sudo mkfs.xfs -m reflink=1 /dev/nvme0n1p1
```

  `/etc/fstab`:

```text
/dev/nvme0n1p1  /var/lib/vortanix  xfs  defaults,noatime,prjquota  0 2
```

- Держите кэш установки на той же файловой системе, что и серверы
  (`/var/lib/vortanix/install-cache` рядом с `/var/lib/vortanix/servers`). Иначе
  копирование не сможет использовать `reflink` и сделает полную копию.
- `noatime` убирает запись при каждом чтении.
- Для NVMe подходит планировщик ввода-вывода `none`, для SSD `mq-deadline`:

```bash
cat /sys/block/nvme0n1/queue/scheduler
```

## Что умеет сама панель

В **Администрирование → Настройки → Узлы**, секция «Скорость и изоляция серверов»
(всё выключено по умолчанию, включайте по одному на тестовом узле):

| Настройка | Что даёт |
|---|---|
| Кэш установки игр на узле | Игра скачивается на узел один раз, новые серверы копируются из кэша |
| Делить CPU по объёму памяти | При занятом процессоре сервер с большим объёмом памяти получает больше времени |
| Мягкий лимит памяти | При нехватке памяти ядро сначала забирает её у серверов, превысивших долю |

SteamCMD при установке всегда работает с низким весом процессора, поэтому установки
не отнимают время у работающих серверов.

## Как проверить результат

1. Откройте **Администрирование → Производительность** до и после изменения и
   сравните один и тот же период.
2. На узле: `top` или `htop` для процессора и памяти, `iostat -x 1` для диска
   (`%util` и `await`), `netstat -su` для потерянных пакетов UDP.
3. Меняйте по одной вещи. Если изменение не видно в цифрах, верните как было.
