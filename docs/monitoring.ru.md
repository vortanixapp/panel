# Мониторинг

[English](monitoring.md) · [Русский](monitoring.ru.md)

Prometheus и Grafana рядом с панелью. Они показывают, как ведут
себя API, база данных и relay под нагрузкой, чтобы медленные места искать по
цифрам, а не наугад.

## Работает из коробки

Prometheus и Grafana входят в стек панели: запускаются вместе с ней и обновляются
вместе с ней, вручную ничего включать не нужно. На уже работающей панели они
появляются после обновления, которое их приносит (служба обновления сама
запускает новые службы). Если образы не удалось скачать, панель всё равно
обновляется, а мониторинг остаётся как есть.

Вместе они занимают до 0,9 ГБ памяти (лимиты 512 МБ и 384 МБ) и пару гигабайт
диска под метрики (`PROMETHEUS_RETENTION_SIZE`).

## Где взять данные для входа

**Администрирование → Настройки → Мониторинг** показывает всё в одном месте:
адрес Grafana (собирается из адреса, по которому вы открыли панель, поэтому
работает и на домене, и на IP), логин, пароль с кнопками «Показать» и
«Копировать», состояние Grafana и Prometheus, срок хранения и источники метрик.

Grafana слушает порт `3001` машины (`GRAFANA_PORT`), поэтому домен не нужен.
Откройте `https://<IP машины>:3001`. Сертификат создаётся при первом запуске и
самоподписанный, поэтому браузер один раз предупредит: продолжайте, соединение
всё равно зашифровано. Если есть файрвол, откройте порт 3001. Чтобы не выставлять
Grafana в интернет, задайте в `deploy/.env` `GRAFANA_BIND=127.0.0.1` и заходите
через SSH-туннель (`ssh -L 3001:127.0.0.1:3001 user@host`).

Логин `admin`, пароль — `GRAFANA_ADMIN_PASSWORD` из `deploy/.env` (его создаёт
`scripts/init-env.sh`); если значение пустое, создаётся случайный. Он применяется
при самом первом запуске Grafana, потом его меняют на странице профиля Grafana, а
панель продолжает показывать первоначальный. Дашборд **Vortanix: обзор** ставится
сам.

Prometheus не публикуется совсем и доступен только внутри сети Docker: у него нет
своего входа по паролю. Любой запрос к нему можно выполнить в Grafana: **Explore**,
источник Prometheus. Срок хранения задают `PROMETHEUS_RETENTION` (15 дней) и
`PROMETHEUS_RETENTION_SIZE` (2 ГБ), срабатывает то, что наступит раньше.

Те же ключевые графики есть и в самой панели: **Администрирование →
Производительность**. Там не нужен ни дополнительный порт, ни пароль, и работает
это одинаково на домене и на IP.

## Обновления и перенос панели

- **Обновления.** Мониторинг обновляется вместе с панелью. Его конфигурация
  (`deploy/monitoring`) приходит с файлами выпуска, как и остальной `deploy`.
  Метрики и настройки Grafana лежат в томах Docker и переживают обновления.
- **Перенос панели.** Переносятся база, загрузки и секреты, данные мониторинга
  нет: на новой машине графики начинаются с нуля, а пароль Grafana создаётся
  заново (см. [panel-transfer.ru.md](panel-transfer.ru.md)).

## Что показывает дашборд

- Запросы к API в секунду и время ответа p95 по маршрутам, ошибки 5xx.
- База данных: время запросов p95 для пулов записи и чтения, медленные запросы,
  занятые соединения пула и время ожидания свободного соединения.
- Горутины и память API.
- Запросы и время ответа relay (трафик агентов).

## Как читать

- Маршрут с высоким p95 и большим числом запросов в секунду оптимизируют первым.
- Если «Соединения пула базы» упираются в лимит и растёт «Ожидание соединения из
  пула», пул мал или часть запросов слишком долго держит соединение.
- Медленные запросы здесь только считаются, текст запроса пишется в лог API как
  `slow query ... sql=...`. Порог задаёт `DB_SLOW_QUERY_MS` (по умолчанию 500 мс).

## Профилирование

Чтобы снять профиль CPU или памяти API, добавьте в `deploy/.env` строку
`PPROF_ADDR=127.0.0.1:6060` и пересоздайте сервис `api`. Адрес находится внутри
контейнера и через Caddy не публикуется. Профиль снимается в контейнере, а
разбирать его можно где угодно:

```bash
docker compose -f deploy/docker-compose.yml exec api wget -qO /tmp/cpu.pprof "http://127.0.0.1:6060/debug/pprof/profile?seconds=30"
docker compose -f deploy/docker-compose.yml cp api:/tmp/cpu.pprof .
go tool pprof cpu.pprof
```
