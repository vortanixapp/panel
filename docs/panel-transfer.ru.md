# Перенос панели на другой сервер

[English](panel-transfer.md) · [Русский](panel-transfer.ru.md)

Документ описывает штатный перенос панели управления с одной машины на другую:
состав переносимых данных, оба режима переноса, требования к новой машине,
порядок переключения DNS и игровых узлов, а также разбор отказов.

Раздел панели: **Администрирование → Перенос панели**. Он доступен только
владельцу панели и недоступен по ключам API: операция выдаёт наружу ключ
шифрования `SECRETS_KEY`, дамп базы целиком и получает root-доступ к новой
машине. Делегировать её отдельным правом нельзя.

## Состав переноса

| Часть | Источник | Назначение |
|---|---|---|
| База данных `vortanix` | том `vortanix_postgres` | пользователи, серверы, платежи, настройки |
| Загруженные файлы | том `vortanix_uploads` | аватары, логотип, вложения обращений, архивы каталога |
| Секреты `deploy/.env` | файл на машине панели | `SECRETS_KEY`, `JWT_SECRET`, доступы SMTP, OAuth, реестра образов |

Не переносится:

- кэш Redis — собирается заново;
- сертификат Let's Encrypt — выпускается заново на новом адресе;
- файлы игровых серверов — остаются на игровых узлах;
- `POSTGRES_PASSWORD` и `INTERNAL_SECRET` — это внутренние пароли машины,
  на новой машине остаются её собственные, сгенерированные при установке.

Адресные переменные `SITE_ADDRESS`, `RELAY_PUBLIC_URL` и `FRONTEND_URL`
не переносятся: их задаёт сценарий `scripts/init-env.sh` на новой машине.

## Требования к новой машине

- Debian или Ubuntu, архитектура x86_64 или aarch64;
- доступ по SSH под `root` либо под пользователем с `sudo` без пароля;
- свободные порты 80 и 443, для режима по IP также 8443;
- свободное место не меньше трёхкратного объёма переносимых данных плюс 5 ГБ;
- домен, A-запись которого будет указывать на эту машину, если панель работает
  по домену.

Docker устанавливать заранее не требуется — панель установит его сама.

## Режим по SSH

Панель сама устанавливает себя на новую машину и переливает данные. Порядок
действий: указать доступ к новой машине, выбрать адрес, при необходимости
оставить включённой остановку записи и запустить перенос.

Стадии видны в разделе и записываются в журнал задачи:

| Стадия | Действие |
|---|---|
| `prepare` | опрос состава данных и их объёма |
| `freeze` | перевод текущей панели в режим только чтение |
| `probe_target` | проверка операционной системы, места и портов |
| `install_docker` | установка Docker |
| `clone` | получение файлов панели той же версии в `/opt/vortanix` |
| `init_env` | `scripts/init-env.sh` с выбранным адресом |
| `compose_up` | запуск стека и ожидание готовности |
| `transfer` | передача базы, секретов и файлов одним потоком |
| `health` | проверка новой панели |
| `relay_cert` | ожидание сертификата relay (только для режима по IP) |
| `agents` | переключение игровых узлов на новый адрес |
| `done` | перенос завершён |

Данные передаются потоком: дамп снимается и сразу уходит на новую машину,
промежуточный файл не создаётся, порт службы обновления наружу не публикуется.
База восстанавливается одной транзакцией, файлы распаковываются во временный
каталог и переносятся переименованием, поэтому обрыв связи не оставляет
половины данных.

Исходная панель после переноса продолжает работать в режиме только чтение.
Выключить её следует вручную, убедившись, что новая панель работает:

```bash
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.images.yml down
```

## Режим архива

Применяется, когда доступа по SSH с панели на новую машину нет.

1. В разделе **Перенос панели → Архивом** задайте пароль не короче двенадцати
   символов и скачайте архив `.vxt`. Архив зашифрован: ключ выводится из пароля
   функцией scrypt, данные закрыты AES-256-GCM почанково, обрезанный или
   изменённый файл при проверке отклоняется.
2. Установите панель на новой машине обычным порядком по
   [инструкции по установке](install.ru.md). Версия должна быть не старше
   версии, с которой снят архив.
3. На новой панели войдите владельцем, откройте тот же раздел, нажмите
   «Проверить архив» — панель покажет версию, дату и объём данных, — затем
   «Заменить данные панели».

Архив содержит `SECRETS_KEY`. Файл следует хранить как пароль: по нему
восстанавливаются ключи платёжных шлюзов, пароли SSH локаций и приватный ключ
TLS relay. Выгрузка и загрузка архива записываются в журнал действий.

## Режим только чтение

Остановка записи включена по умолчанию при запуске переноса. В этом режиме
панель отвечает `423` на любые изменяющие запросы, кроме входа, выхода и самого
раздела переноса; воркер не берёт новые задачи выдачи серверов, резервного
копирования, рассылок и списаний, начатая задача доигрывается.

После успешного переноса режим остаётся включённым: так пользователи не пишут
в устаревшую копию, пока DNS ещё указывает на старую машину. Снять его можно
кнопкой в разделе переноса — панель предупредит, что изменения не попадут
на новую машину. При отказе или отмене переноса режим снимается сам.

## Адрес панели и DNS

**Тот же домен.** Новая панель получает тот же `SITE_ADDRESS`. Сразу после
стадии `done` переключите A-запись домена на новую машину. Сертификат
Let's Encrypt выпустится на новой машине при первом обращении, игровые узлы
переподключатся сами — их адрес не изменился.

**Новый адрес.** Новая панель поднимается на указанном домене или IP-адресе
и сразу доступна. Игровые узлы панель переключает сама на стадии `agents`.

## Игровые узлы

При смене адреса панель обходит локации по SSH и пересоздаёт контейнер
`vortanix-agent` с новым `RELAY_URL`, а в режиме по IP — и с новым отпечатком
сертификата relay. Токен узла передаётся через стандартный ввод и в аргументах
команд не появляется.

Узлы, которые переключить не удалось, показаны счётчиком в ходе переноса.
Повторить переключение только по ним можно кнопкой «Повторить переключение»
в том же разделе, указав доступ к новой машине. Вручную узел переключается
командой установки агента со страницы локации новой панели.

## Разбор отказов

**Мало места на новой машине.** Проверка выполняется до любых изменений,
перенос останавливается на стадии `probe_target`. Исходная панель не затронута.

**Порт 80 или 443 занят.** На новой машине уже работает веб-сервер. Остановите
его или переносите на чистую машину.

**Обрыв связи на передаче.** Задача завершается ошибкой, режим только чтение
снимается. Повтор безопасен: восстановление базы выполняется одной транзакцией.
Для повторного запуска выполните перенос заново — файлы панели на новой машине
останутся, будет обновлён только их состав.

**Новая панель не поднялась за отведённое время.** Журнал стека на новой
машине:

```bash
docker compose -f /opt/vortanix/deploy/docker-compose.yml logs --tail 100 api
```

**После переноса не открываются аватары и логотип.** Не доехал том
`vortanix_uploads`. Убедитесь, что на исходной машине контейнер `api` был
запущен во время переноса, и повторите перенос.

**После переноса в настройках касс пустые ключи.** Не совпал `SECRETS_KEY`.
Такое возможно, если данные восстанавливались не через раздел переноса.
Значение переносится в составе секретов; сверьте его в `deploy/.env` на обеих
машинах.

**Узел остался в состоянии «не в сети».** Проверьте с узла доступность нового
адреса relay и журнал агента:

```bash
docker logs vortanix-agent --tail 50
```
